## How To Read The Map

Each current file has exactly one row and disposition. A normal row has one
final owner and planned target. Two Step 3 declaration-split rows partition
the mixed cache declaration and facade declaration files between named owners
and targets; neither duplicates a declaration. A feature-closure move happens only in
its later single-feature transaction. A `merge` row contributes reviewed exports to
`implementation/index.js`; it does not preserve the old barrel. Internal
owners are non-public mechanisms outside `implementation`. Interface owners
are declaration-only global contracts.

## Interface And Value Ownership

Global declaration owners cover Algorithm32, atmosphere, cache-backend, color,
geometry, ground-boundary, light-source, physical-quantity, and
spectral-quantity behavior and values.
`AtmosphereModel` remains the built-in capability contract implemented by
`CanonicalAtmosphere`. The Step 3 contract owns the exact declaration split:
the public cache-backend contracts leave the mixed GPU-runtime declaration.
Concrete implementation-local declarations remain with their feature.

`SpectralBasis` and `SpectralPacket` are public readonly interfaces describing
shared values produced by built-in code, not caller-selectable implementation
features or caller-implementation seams. The target Algorithm32 configuration
has no spectral-basis property. The facade selects and constructs native-15
values with the standard non-public spectral builders and native-15 profile.
The concrete builders and math remain under `spectral-values`; another basis
requires a future explicit API revision. Caller-authored spectral bases,
packets, irradiance distributions, reflectance distributions, and other custom
spectral inputs are deferred; no public spectral builder, factory, or
configuration record is part of this target.

Repository-owned validation profiles are not caller customization. Mandatory
post-extraterrestrial production Stage 13 will add the fixed Bruneton
paper-comparison construction and regeneration path outside
`implementation/` and the public facade; it is not part of this 295-row reorg
or its Step 3 contract.

The native-15 profile is public readonly configuration data, not an
implementation feature. Its default, override builder, constants, declarations,
and tests remain under `profiles/native-15`, with `profiles/index.js` as its
value export surface.

An immutable profile, request, result, descriptor, quantity record, or string
union remains a data contract rather than receiving a nominal interface.
Step 3 may split a declaration file mechanically when public interface/data
contracts and implementation-private declarations currently share that file;
the source row remains owned by the destination recorded here.

## Shared Non-Public Owners

- `shader-assembly`, `gpu-cache-runtime`, `rendering-runtime`, and
  `atmospheric-transport` own cross-feature execution mechanisms.
- `sampling-domains` owns the current position/direction domain classes,
  fixed domain instances, indexing and stencil behavior, declarations, and
  tests. They are cache-construction internals because no public configuration
  accepts a caller-selected domain.
- `geometry-support`, `light-source-support`, and `ground-transport` own
  behavior shared by sibling concrete features; no implementation may
  deep-import a sibling's private closure.
- `spectral-values` owns the current concrete spectral value builders and
  operations. `physical-quantities`, `math`, `time`, `validation`, and
  `value-identity` own other reusable internal operations.
- `reference-execution` owns executable reference orchestration, while
  `reference-evidence` owns retained fixtures and reference documentation.
- `repository-support` retains the Algorithm32 root documentation and
  configuration.

These internal owners are not public implementation packages and do not export
through `implementation/index.js`. Application deep imports of their current
modules must be replaced during the owning feature/application transaction.

## Closed Decisions

- `FlatSynchronizer` is private synchronization support within `flat-earth`,
  not a public implementation or a local-Sun/geometry interface. Algorithm32
  passes the facade's latitude, longitude, and instant observation to geometry
  when asking it to configure the atmospheric light source. The
  current Flat32 local-source projection moves into `flat-earth`; its spherical
  observer-frame direction calculation moves into `spherical-earth`. Flat32
  retains UI and preset selection but computes neither placement. A genuinely
  identical solar-time calculation needed by both geometries may move to a
  specifically named non-public owner during manifest review. Celestial source
  ownership is unchanged and remains deferred to the extraterrestrial
  production stage.
- Cubed-sphere, Fibonacci, paired-Fibonacci, and spherical-native domains are
  shared cache-construction internals under `sampling-domains`. A future
  public domain-selection seam requires a separate API revision.
- Native-15 is public profile data under `profiles/native-15`, not an
  implementation feature.
- Spectral basis and packet are readonly shared value contracts. Their current
  concrete builders are internal, and the Algorithm32 facade constructs the
  standard native-15 values without a public spectral override.
- Built-in public constructors obtain required native-15 values from their
  owned defaults. Custom caller spectral data is not a supported constructor
  capability in this reorganization.
- `implementation/uniform-lambertian-ground` initially exposes only the named
  built-in grass material and internally resolves its native-15 albedo packet.
  Snow is deferred until its physical profile is selected. Ocean is a later
  stretch goal and receives no target owner, export, placeholder, or contract
  in this reorganization.
- Public interfaces describe built-in capabilities in this plan; they do not
  establish a supported third-party implementation SDK. Cache, construction
  domain, and shader extension surfaces remain internal.
- Geometry- and light-source-specific Three adapters stay with their concrete
  feature. The general React/R3F integration and the generic Three cache backend
  remain independently selectable features.
- No `star-field` target exists yet. It is created only with a future
  implementation and does not revive retired Algorithm32-Star material.
- No target uses an immediate implementation folder named `runtime`, `cache`,
  `gpu`, `shader`, `utils`, `shared`, or `types`.
