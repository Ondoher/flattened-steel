## Objective

Use the standalone Algorithm32-Star CPU, GPU, provenance, and immutable-run
infrastructure to determine whether the proposed whole-flat-world atmosphere
boundary, two-center nonlinear position index, sparse interpolation topology,
and exact ragged transport representation can reproduce the explicitly
selected physical model and justify a later production proposal.

For the factorized base-fact shell study, accuracy and packed resident bytes
are characterization outputs over the predeclared count ladder. Whether one
specific cache satisfies frozen numerical and resource gates is a later
selection question requiring a separate plan and fresh independent evidence.
Any descriptive experiment timing remains offline characterization, not
production GPU latency or proof of animation cadence.

This is not a request to recover a missing Star flat/local implementation.
Star has no integrated flat/local N-order cache. The plan creates a new
engineering study while reusing only the explicitly pinned primitives and run
mechanics that already exist.

All work follows the
archive-internal `scripts/algorithm32-star/experimental-lane-rules.md`.
The
[cache design](../cache/cache-design.md#proposed-flatlocal-dome-aware-nonlinear-position-index)
owns the completed prior v2-v4 lineage, its topology, resource arithmetic,
metrics, gates, and promotion boundary. Those gates and its resident ceiling
do not govern the new shell characterization. The
[local-Sun cache design](../cache/local-sun-cache-design.md)
owns the independent radial and atmosphere fact tables, inverse-square count
ladder, characterization metrics, packed resource formula, minimum-width
limit, and cache-fingerprint handoff. The
[Flat32 application design](../production/flat32-migration-inventory.md#future-application-cache-quality-profiles-and-feature-policies)
owns later profile resolution, controls, feature overrides, and time-animation
lifecycle. No concrete application profile or override resolver is selected
by this plan. The
[flat-world boundary decision](flat-world-atmosphere-boundary-decision.md)
owns the shared selected physical boundary.
The
[selected cache contract](../cache/cache-contract.md#stored-quantity-and-recurrence)
remains the owner for field quantities, recurrence, selected spectral and
direction domains, construction controls, and ground participation. The
[flat/local promotion register](../flat-local/unresolved-research.md)
continues to own selected production status and evidence.
This plan owns execution order, source placement, run boundaries, and current
status.

## Authority And Independence

The study has four distinct authority layers:

1. Analytic geometry owns exact shallow-cap points, stable atmosphere-exit
   distances, contact classifications, and reflection identities.
2. Unchanged hash-pinned Star atmosphere, local point-Sun, spectral, `L1`,
   node-level `J2`, direct-`J2`, and generic CPU-field primitives may evaluate
   the behavior they already implement.
3. A separately written dense binary64 N4 reference owns higher-order
   engineering scoring within this lane only after its own structured-grid
   convergence gate passes.
4. The sparse position topology, ragged transport, and GPU realizations are
   candidates scored against those authorities; they never score themselves.

The initial reusable Star paths are the ones identified by the cache design,
including:

- `src/model/CanonicalAtmosphere.js`;
- `src/model/LocalPointSun.js`;
- `src/spectral/canonical-basis.js`;
- `src/cache/l1-field.js`;
- only the exported node integrator from
  `src/cache/local/build-local-j2-cache.js`;
- `src/oracle/direct-j2.js`; and
- generic arbitrary-domain and CPU-field containers that do not impose the
  old rectangular local cache.

Paths above are relative to `scripts/algorithm32-star`. Every reused file and
transitive dependency is enumerated and hashed by each deciding run. The old
local cache descriptor, old local cache interpolation, provisional case, and
local-dome GPU runner are patterns or negative controls only.

The study imports no `src/algorithm32` module and writes nothing into the
sealed Star parity artifact. The dense reference imports neither production
nor the sparse candidate domain or locator.

The
[Star parity data-set boundary](../production/star-parity-data-set.md#decision)

## Fixed Non-Goals

The experiment will not:

- edit or adopt the old Star rectangular `z`/`rho` cache;
- describe the new geometry or integrated recurrence as recovered Star
  behavior;
- import current production and compare production with itself;
- select a node count, topology, or tolerance from camera images;
- use San Jose or Union Glacier subjective scenes as numerical oracles;
- alter the physical source distance, inverse-square behavior, atmosphere
  density, world radius, or atmosphere exit to meet a resource limit;
- select or implement an application cache quality profile, time-animation
  override, cross-profile reuse policy, or runtime profile control from the
  initial slice output;
- implement GPU work before the corresponding binary64 study reaches its
  predeclared terminal condition; or
- promote anything to production merely because a run is accepted.
