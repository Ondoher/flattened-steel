# Shared Cache Calculation Reuse Experiment Plan

## Acceptance Gate

Can dependency-based planning and retained GPU execution reproduce the application controls exactly with less work or lifecycle overhead than the qualified shared generator, then preserve the separate direct-40 profile?

## Work

- [x] E0: Establish the contained experiment, comparison authorities, output contract, and active topic. Creation does not start execution.
- [x] E1: Authenticate application controls and shared-package evidence. Inventory requested outputs, stored unique results, existing sharing, and additional candidate work reuse without regenerating caches. Audit dependencies and identify missing evidence.
- [x] E2: Build a planning-only proof with empty, repeated, reordered, overlapping, and larger input lists, plus dependency changes that must prevent reuse. Reconstruct every control exactly through inventory indexes. Distinguish storage savings from avoided work.
- [x] E3: Select supported optimizations and pin resource budgets and improvement criteria. Implement the smallest retained GPU execution proof, with immutable runs and progress reporting before long operations. Establish exact computation on a focused subset before widening.
- [x] E4: Recompute all application controls and verify exact reconstruction. Compare work counts and phase costs with the qualified shared generator. Exercise bounded residency, reload, cancellation, cleanup, and increasing inputs; report metadata, disk, and memory growth.
- [x] E5: Verify compatibility against existing 17-scene direct-40 data with its correct ground contribution and complete profile. Keep fixed benchmark acceptance separate from optimization equivalence.
- [x] E6: Consolidate correctness, lifecycle, containment, provenance, and performance evidence; decide whether to reject, iterate, retain, or propose promotion. Retain the qualified experimental candidate; overall runtime improvement and production promotion remain unclaimed.

## First Effort Checkpoint

At the end of E1, report existing sharing, additional avoidable work, dependency
justification, estimated benefit, evidence gaps, and the cost of the next proof.
Continue only when execution is authorized and value and effort remain clearly
reasonable; otherwise pause for reevaluation. The owner may provide periodic
credit readings. This plan establishes no fixed execution deadline or speedup.

## Verification Cadence

Use focused proof runners and changed-mechanism reviews. Reuse authenticated
unchanged evidence and reserve full candidate reconstruction and consolidated
review for their final gates. Do not repeat broad production suites for isolated
analysis or documentation. Exactness, valid references, complete requests,
bounded active resources, and preserved parent evidence are mandatory gates.

## Promotion Boundary

Experiment results are evidence, not production architecture. Promotion requires a separate production-owned design, implementation plan, and verification boundary.
