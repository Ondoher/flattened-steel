## Findings by scene

**A:** Page settings is a readable, directly addressable button immediately after the Flat Earth selector. The shifted camera group remains on one line with comfortable separation; Elevation, Vertical FOV and Center on Sun retain their labels and exact values. Both shared accepted summaries remain visible while configuration is closed. The addition makes page-specific access visible without introducing another workspace page.

**B:** Both view headers show Page settings beside their own page selector. The View 2 close action remains distinct at the right edge of its identity row, with no collision or confusion with the camera controls. The Configuration title, Close, Settings for label and Shared settings selector fit the 360px inspector. Moving the body down preserves the expanded coordinate editor and complete date/time editor; the bottom Use date and time button is fully visible with space beneath it. The explicit shared target replaces the former scope sentence without losing the reading order of Location before Date and time.

**C:** Each paired 550px header contains the new page shortcut and its existing camera row. The bottom Configuration heading, inline target label/select and far-right Close occupy separate readable positions. The selector does not intrude into either task column. The two scenes remain simultaneously visible, and the location disclosure/attribution row and date/time action remain contained. No added vertical height is needed for this captured state.

**D:** The 600px layout preserves a visible Page settings entry and complete camera controls. Within the bottom-panel header, Configuration at left, the stacked Settings for label/select in the middle, and Close at right fit without overlap. Shared settings remains legible inside the closed selector. The two task columns start below this header, with Date, Time and their action still fully visible. The added navigation has not reduced the scene or obscured the lower form action. The selected default state fits; longer targets, larger type and expanded coordinates are not established by this screenshot.

**E:** Settings for and the Shared settings selector sit clearly in the brand row, above the single inline editor. Both page shortcuts remain visibly associated with their own Flat Earth selector. The inline city/date-time forms retain separate accepted-value readouts, device-time meaning and the local date/time action. There is no second inspector or global Apply. This image illustrates the shared inline target only; it does not demonstrate the later inline view-target transition.

**F:** The intended view-specific meaning is clear. Only View 2's Page settings shortcut is filled blue; View 1's is outlined. Configuration remains blue to indicate the host is open. Neither shared summary retains the Location-active underline. The full location/date-time summaries remain readable above the views, while the panel selector explicitly says View 2 — Flat Earth. The Camera section contains only Elevation 5 m and Vertical FOV 50°, followed by Changes affect View 2 only. Those displayed values match View 2's toolbar. No Apply, global-default wording, invented settings category or duplicate shared editor is visible. The unused panel area remains quiet. Matching displayed numbers do not by themselves prove that controls share underlying state; that ownership remains the specified intended behavior.

## Shared observations and limits

The prior palette correction is preserved: ordinary outlined commands and input borders appear white on the dark surface, while blue distinguishes open/selected entries and filled actions. New controls use the same type, corners and scale as the existing family. No visible control clipping, cross-pane overlap, truncated target value or contradictory scope indication was found. The parent report records no horizontal-containment issues or capture errors and one painted hint per view; these mechanical checks support the exact captured states without establishing other layouts or runtime behavior.

The visible extension addresses the owner's concern: every depicted page has a named settings entry, and F demonstrates a distinct view target in the same configuration surface. The particular Camera provider remains an illustrative contribution to the already-accepted extension contract. These PNGs do not show that such a provider is currently registered in the application or establish a final page-settings inventory. Keep that qualification in the gallery rather than inside the depicted product UI.

Only closed native selectors and valid, ready, unfocused states were inspected. Option-popup contents, keyboard/focus behavior, provider mounting and cleanup, target transitions, draft policy, asynchronous updates, absence-of-provider behavior, localization, zoom and additional window sizes were not exercised. The reused actual scene asset remains layout illustration, not verification of projection at every pane aspect ratio. Original-family evidence and this revision remain separate; no app implementation was inspected or changed.
