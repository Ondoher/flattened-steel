# Continuation closure

`summarizeContinuation(C0, options)` authenticates the complete terminal inventory
before allocating a new C6 CPU report. Options select accepted C2/C3 assessments,
name required members of the complete C4 assessment inventory, and supply an
explicit `skipped` or `not-executed` C5 decision with its supporting run paths.
Missing assessments produce a limited report. No numerical or full qualification
is inferred from a missing phase, accepted execution, or improved Kider score.

The reporter scores every actual ordinary N1–N4 capture selector, preserves
producer-normalized assessment tables, rechecks C1 residual identities and C4
forecasts, and reproduces local-J2 angular allowances. Historical full-boundary,
new screen, biased component and source-density quantities remain separate.
The one registered progress-invalid proof is accounted for through its exact
exception owner; every other source must pass strict terminal verification.

All generated evidence stays in the new run. The forecast is 12 MiB within C6's
20 MiB allocation, with 1 MiB reserved for terminal metadata. Source snapshots and large tables use lossless gzip; no
scattering fields or caches are retained. `figures.mjs` prepares up to twelve
data requests. The root-owned `plotting/` adapter renders PNGs in memory with
the installed Windows .NET charting library and records its actual tool hashes.
Every planned screen capture appears in the plots, using working view8 where
available; all other selectors remain in the complete score tables.

`closureImplementationProof()` is a pure manufactured proof API. It allocates
no evidence run and checks selector boundaries, density/radiance separation,
CSV round trips, source joins, independent SSE arithmetic, and failed/invalid
resource debits. `verifyClosureTables()` repeats table checks on actual report
data. The root owns proof execution, source-review gates and scientific runs.

Resource tables describe the terminal inventory before this report. Its own
seal adds exact bytes and elapsed time; the final read-only reconciliation checks
the complete ledger and emits self-inclusive counters to command output.
