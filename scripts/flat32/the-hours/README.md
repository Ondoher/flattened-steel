# Production The Hours qualification

This adapter reproduces the protected The Hours seed, observatory geometry,
camera score, original nine-key astronomical timeline, local sand reflectance,
stellar filters and deterministic30FPS recording workflow through ordinary
Algorithm32 and Flat32 owners. It does not import an experiment at runtime,
intercept bundles or mutate private geometry. The candidate remains separately
selected; production defaults and publication belong to P4.

Tracked source belongs here. All new output, profiles, captures, decision
records and sealed accepted/rejected runs belong to
`.codex-tmp/p3-strobing-20261007/`. Retained D-drive evidence is read-only.
Each run records source, dependency, tool, input and output identities. SHA-256
manifests and exact parent pins preserve the complete derivation chain.

Capture and comparison delivery require the explicit environment setting
`ALGORITHM32_THE_HOURS_EVIDENCE_ROOT` pointing to the read-only relocated
evidence directory. No machine-specific path is embedded in the adapter.
Task-local qualification paths resolve from this repository identity.

Run `node capture.js proof` for complete package metadata/encoded-block
authentication, actual two-atlas GPU allocation/readback and P2/P9/Basic
CPU/GLSL color checks. `scenes` traverses all109 production scene ordinals
through the normal location/time and publication APIs. This diagnostic uses a
great-circle observer route around the fixed midday Sun; the full film instead
retains the original San Jose observation and camera choreography.

The `daylight`, `sunrise`, `sunset` and `early-ground` operations retain the
original half-float control. Their `-float32` counterparts explicitly select
the source-precision candidate. Each short retains every native PNG, physical
packet/publication trace and an unannotated original-workflow AVC recording.
`qualify.js <capture-root> <manifest-bytes> <manifest-sha256>` validates exact
native PNG/source means, the original scaled detector, independent x264
slow/high5.2/40Mbps encoding, and the original Mediabunny/WebCodecs workflow.
Explicit `--workflow-bitrate=80000000`, `--workflow-bitrate=160000000` and
`--software` select registered media diagnostics from unchanged native PNGs.
Rejected media policies are retained. Source values and detector limits remain
fixed: every regional curvature ratio at most1.5, at most one distinct
reversing publication, and upper-sky excursion at most one mean display code
over a complete89.5–91.5-degree horizon crossing. The112/125 neighborhoods
are additionally measured regardless of strongest-event ranking.

`capture.js film <short-selection-json> <bytes> <sha256>` authenticates all
four accepted short proofs before rendering3840×2160,60seconds,1800frames.
The admitted native4K policy is80Mbps; matched720p diagnostics use160Mbps.
Both use the original AVC high5.2 hardware-first workflow and exact ideal
cadence. `qualify-film.js` takes the closed film root and its exact manifest
identity, verifies every state/presentation slot and both horizons, evaluates
native-source and decoded recurrence, checks lossless milestones against their
source means, and derives the1024×576 review copy. Native owner inspection
remains a separate required acceptance gate.

Integer-second diffuse/adaptation endpoints are actual production GPU
measurements. Fractional endpoints use production monotone cubic interpolation;
direct light is sampled at the exact original instant. Per-frame camera values
are checked against the production-derived score and then taken from the exact
authenticated original trace to preserve binary64 rounding.
